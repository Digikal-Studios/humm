# M2 Benchmark Comparison

Same criterion suite as M1 (`crates/humm-core/benches/export.rs`,
`crates/humm-media/benches/decode.rs`, `crates/humm-whisper/benches/e2e.rs`),
re-run at the close of M2 against the `docs/benchmarks/M1.md` baselines. Per
`CLAUDE.md`, a regression on `e2e/decode_transcribe` (the real
decode+transcribe path a user exercises) is milestone-blocking; `export` and
`decode` are supporting baselines for their own adapters/writers.

## Host

- Chip: Apple M4 (10 cores: 4 performance + 6 efficiency) — identical machine to M1.
- RAM: 32 GiB (34 359 738 368 bytes)
- macOS: 26.5.2 (build 25F84) — identical to M1.
- Rust profile: `[profile.release]` — `lto = "thin"`, `codegen-units = 1` (workspace root `Cargo.toml`, unmodified since M1).
- Model: whisper `tiny`, GGML, GPU (Metal) on.
- Fixture: Buzz's `whisper-french.mp3` testdata (`HUMM_BUZZ_TESTDATA`, same fixture as M1).
- Run **sandbox-lifted** (`dangerouslyDisableSandbox`) per the M1-documented finding that this
  coding harness's sandboxed shell segfaults inside ggml's Metal allocator on GPU model load —
  an environment property of the sandbox, not of humm's code. Same precedent as Task 7/8/9/11's
  `models::` TCP-bind tests.

## Verdict: no regression — every bench improved

**No transcription-path (or any other tracked) regression.** All five benches
came in faster than their M1 baseline, `e2e/decode_transcribe` included
(−52.4%, well outside CI-width noise on either run).

**Read this as host-state variance, not a code speedup, for `export` and
`decode`:** `crates/humm-core/src/export.rs` has not changed since M1's
commit `49078a8` (`git log` confirms — no commits touch that file in M2), yet
`export/write_srt` — a pure-Rust, no-I/O, no-subprocess bench — is 53.8%
faster on identical code on the identical machine. That rules out any M2 code
change as the cause for at least the `export` benches, and points instead to
this being the same "developer's primary laptop, not an isolated benchmark
rig" that M1.md already flagged: less background load / better thermal state
this run. `decode` and `e2e` shell out to real `ffmpeg`/whisper-rs
subprocesses (`e2e` also loads a real GPU model), so some of their
improvement could additionally reflect warm OS/disk caches or Metal driver
state from repeated recent runs on this machine — but the pure-Rust
`export` result is the clean signal that the dominant factor here is host
variance, not a regression risk to chase, and (by the same logic) not
grounds to claim a genuine ~50% engine speedup either. No humm code in the
decode/transcribe/export path changed in M2 (M2's work was store/queue/CLI/
downloader/URL-import layers, all upstream or downstream of this pipeline);
this reinforces reading the deltas as environmental rather than causal.

Net: the milestone gate (no regression on the transcription path) is
satisfied with margin; no fix required; nothing to report as BLOCKED.

## Reproducing

```bash
export CARGO_HOME="$(git rev-parse --show-toplevel)/.cargo-home"
cargo bench --workspace
```

Same skip behavior as M1: `decode`/`e2e` print a line and register no
measurements (exit 0) when `ffmpeg`, the Buzz testdata, or (for `e2e`) a real
cached `tiny` model is unavailable; `export` always runs.
