# M7 Benchmark Comparison & Acceptance

Per `CLAUDE.md`'s regression rule and the standing lesson `docs/benchmarks/M5.md`
§1.2 established and `docs/benchmarks/M6.md` §1 repeated: **re-baseline against a
same-day checkout of the previous milestone's tip, never against recorded
numbers, and interleave the pairs so both checkouts face the same contention.**
All runs 2026-07-26, sandbox-lifted (Metal), Apple M4 / 32 GiB / macOS 26.5.2,
whisper `tiny` for `e2e`, Buzz `whisper-french.mp3`, criterion 10-sample runs —
the same configuration as M1–M6.

M6 = `git worktree add /tmp/…/humm-m6-bench 2327e80` (M6 tip), its own
`target/`, sharing this worktree's seeded `CARGO_HOME`; M7 = this branch's tip
(`1201ef9`). Binaries verified distinct (`md5` of the two `e2e` bench
executables differ), so the two checkouts really were compiled separately.

## 1. Conditions, stated up front

This machine again carried external, un-pausable load for the whole benching
window — load averages **4.3–9.7** across the runs (vs M6's 10–19, i.e. a
quieter but still busy machine). Absolute numbers are therefore not comparable
across milestones and are meaningless in isolation; every comparison below is
**paired and interleaved**, alternating which checkout runs first.

## 2. Transcription-path regression guard (`e2e`)

`e2e/decode_transcribe/whisper-french.mp3/tiny` — the bench `CLAUDE.md` treats
as blocking. Three interleaved pairs:

| Pair | Order | M7 mean (CI) | M6 mean (CI) | Δ (M7 vs M6) |
|---|---|---|---|---|
| A | M7→M6 | 337.89 ms [328.68, 350.89] | 337.29 ms [322.43, 353.86] | **+0.18 %** |
| B | M6→M7 | 332.41 ms [325.49, 340.14] | 351.44 ms [339.64, 358.08] | **−5.41 %** |
| C | M7→M6 | 338.70 ms [332.60, 347.04] | 336.88 ms [323.29, 347.78] | **+0.54 %** |

Every pair's confidence intervals overlap heavily, and **the sign of the delta
flips** (M7 marginally slower in A and C, clearly faster in B). Pooled means:
**M7 336.33 ms, M6 341.87 ms** — M7 1.6 % faster, which is itself inside the
run-to-run spread and is not claimed as an improvement.

### 2.1 Call-path innocence (`git diff 2327e80..HEAD`)

The paired numbers say "no regression"; the diff says "there is nothing that
*could* have regressed on this path":

- **`crates/humm-media/src/decode.rs` — zero changes.**
- **`crates/humm-whisper/src/engine.rs`** — every hunk is in `transcribe_live`,
  the new `LiveStateSlot`, or the new `begin_live_session`/`end_live_session`.
  The `impl TranscriptionEngine` block that owns the file-path `transcribe`
  the bench calls is **byte-for-byte identical** between the two checkouts
  (verified directly: old lines 230–700 vs new 384–854 diff clean). The one
  new field initializer (`live_state: LiveStateSlot::new()`) runs inside
  `WhisperEngine::load`, which the bench calls **once, outside `b.iter`**.
- **`crates/humm-core/src/pipeline.rs`** (not on this bench's path — it drives
  decode + engine directly — but on the *product's* transcription path): the
  only unconditional addition is
  `if let Some(disposition) = job.output.source_disposition` after the export
  loop, i.e. one `Option` discriminant check when folder watch is not
  involved. The translator poll-join change is inside the existing
  `if let Some(handle) = translator`.
- **`crates/humm-core/src/queue.rs`**: the F-115 pre-hook is gated on
  `self.postproc` being `Some` *and* `cfg.skip.enabled`; `run_on_complete_chain`
  returns immediately when `ctx.postproc` is `None` or when none of
  resize/summary/docx is enabled. **Post-hooks are off by default**, so a
  default-configuration task pays two boolean checks. `Terminal::Completed`
  now carries a `Box<PostCompleteContext>` — one heap allocation per completed
  task (not per segment, not per chunk).

### 2.2 Verdict

**No transcription-path regression. Gate: PASS.** Paired deltas sign-flip
inside overlapping CIs, and the measured call path carries byte-identical code.

## 4. ADR-021 — live whisper-state reuse, measured before/after (§10)

### 4.1 What changed

M7 Task 19 gave `WhisperEngine` a live-session state slot: `transcribe_live`
now reuses one `WhisperState` for a whole session instead of calling
`context.create_state()` per chunk, with `begin_live_session`/
`end_live_session` bracketing it. ADR-021 (written in M5) predicted this
mattered because `whisper_init_state` calls `whisper_coreml_init` under the
`coreml` feature humm builds with — reloading the CoreML encoder every chunk.

### 4.2 Method

The existing `HUMM_SMOKE_LIVE_FIXTURE` acceptance path (M5 Task 14's), real
windowed `humm-gui`, real `WhisperEngine` on Metal, the already-cached `small`
model, Buzz's `audio-long.mp3` decoded through real ffmpeg and streamed at
wall-clock pace, 200 s window per run, isolated `HUMM_*` dirs per run. The
number is the session's own `LiveMeasurement::realtime_ratio()`
(`audio_secs / engine_secs`, silence-skipped batches excluded from both) as
persisted to `settings.recording.measured_speed["small"]`.

A = HEAD (`1201ef9`, state reused); B = `680addc` (= `f24fb29~1`, the commit
before the reuse landed), built in its own worktree with its own `target/`.
Runs interleaved A/B, B/A, A/B.

**Harness note (honest):** pair 1 ran before a stall was diagnosed; pairs 2
and 3 ran under `caffeinate -dimsu` with the app activated after launch and a
watchdog. The stall (`docs/gui-manual/M7.md` §10.3) was the smoke hook's Stop
never firing because UI frames stopped while the window sat occluded — the run
was discarded and re-run, not repaired after the fact. Pair 1's two runs both
completed normally in 201/202 s and are kept.

### 4.3 Results

| Pair | Order | HEAD (reuse) | `680addc` (per-chunk) | Δ |
|---|---|---|---|---|
| 1 | A→B | 2.5473× | 2.6324× | −3.23 % |
| 2 | B→A | 2.7169× | 2.5527× | **+6.43 %** |
| 3 | A→B | 2.6911× | 2.5551× | **+5.32 %** |

**Pooled: HEAD 2.6518× vs 2.5801× → +2.78 % in favor of state reuse.**
Every run cleared the ≥ 1.0× realtime gate with wide margin; every run exited
0 with 33–34 persisted segments and a `completed` store row.

### 4.4 The mechanism, verified directly (not inferred from the ratio)

The ratio delta is small enough to be argued about; the mechanism is not.
whisper.cpp's own logger, counted per run:

| Build | `whisper_init_state` per 200 s session | CoreML encoder loads |
|---|---|---|
| HEAD (reuse) | **1** | **1** |
| `680addc` | **34–35** | **34–35** |

And the cost of one such init, measured from the log's own timestamps in the
`680addc` run (`kv self size` line → `compute buffer (decode)` line, 35
samples): **min 32.7 ms, median 43.8 ms, mean 44.1 ms, max 61.7 ms, total
1.544 s**. That session transcribed 167.6 s of audio (33 segments, last one
ending at 167 600 ms) at a 2.5527× ratio ⇒ ≈ 65.7 s inside the engine, so the
reclaimed 1.544 s is **2.4 % of engine time** — which
predicts a **+2.4 %** ratio improvement. Measured: **+2.78 %**. The prediction
and the measurement agree, and both sit just above the ±3 % run-to-run spread,
which is exactly why a single pair could show the wrong sign (pair 1 did).

### 4.5 ADR-021 addendum — draft text for Task 21

> **Addendum (M7 Task 19/20, measured).** The per-chunk `create_state()` this
> ADR accepted is gone: `WhisperEngine` now creates one `WhisperState` per live
> session and reuses it across `transcribe_live` calls, bracketed by
> `begin_live_session`/`end_live_session`. Verified at the mechanism level —
> one `whisper_init_state` (and one CoreML encoder load) per session instead of
> one per chunk, 1 vs 34–35 in a 200 s `small` session.
>
> **The ADR's cost attribution was wrong, and the measurement corrects it.**
> This ADR (and `docs/benchmarks/M5.md` §3.3) explained the live path's ≈2×
> realtime, against file mode's ≈17×, primarily by the per-chunk CoreML
> encoder reload. Measured on an M4 with the cached `small` model, one full
> `whisper_init_state` — kv-cache allocation, CoreML load, and compute-buffer
> setup together — costs a **median 43.8 ms**, totalling **1.544 s across 35
> chunks** in a 200 s session, i.e. **2.4 % of engine time**. Removing it
> improved the measured realtime ratio by **+2.78 %** (pooled over three
> interleaved before/after pairs: 2.6518× vs 2.5801×) — a real, reproducible
> win, and nowhere near the ~6.8× efficiency gap between live and file mode.
>
> That gap's dominant cause is structural and unchanged: whisper.cpp processes
> a fixed 30 s window per `full()` call, and the live loop hands it ≈5 s
> chunks (`AppendBelow`/`AppendAbove` use `n_batch_samples = 5 s × SAMPLE_RATE`,
> `live/chunker.rs:81`), so roughly six times as much encoder work is done per
> second of real audio. 30 / 4.7 ≈ 6.4 against a measured live-vs-file
> efficiency ratio of ≈6.8 — the padding accounts for essentially all of it.
> Any future attempt to close the live/file gap must attack the chunk-vs-window
> ratio (larger batches, or a streaming encoder), not the state lifecycle,
> which is now already optimal.

## 5. New-surface performance notes (informative, no baseline exists)

- **Folder watch** adds one `notify` watcher thread and one worker thread per
  active watch; the worker blocks on a channel and rescans only on an FSEvents
  delivery — no timer, no polling. Observed end-to-end latency in the windowed
  acceptance runs (`docs/gui-manual/M7.md` §5): drop → mirrored output written
  in **≈1 s** for a 6.7 s fixture on `tiny`, i.e. dominated by inference.
- **Post-processing hooks** are off by default and short-circuit before any
  work (§2.1); no bench added — an enabled hook's cost is its own subprocess/
  network cost (ai_summary is network-bound, docx is a zip write), not a
  regression surface for the transcription path.
- **Locale switching** rebuilds a thread-local Fluent bundle when a generation
  counter changes; the windowed acceptance run showed the whole UI, across
  three simultaneous viewports, re-rendering on the next frame with no
  perceptible pause.

## Reproducing

```bash
export CARGO_HOME="$(git rev-parse --show-toplevel)/.cargo-home"
git worktree add /tmp/humm-m6-bench 2327e80          # same-day M6 checkout
git worktree add /tmp/humm-pre-reuse 680addc         # pre-state-reuse checkout

# Interleaved criterion pairs (lifted; alternate the order between pairs):
cargo bench -p humm-whisper --bench e2e    --manifest-path <checkout>/Cargo.toml
cargo bench -p humm-media   --bench decode --manifest-path <checkout>/Cargo.toml
cargo bench -p humm-core    --bench export --manifest-path <checkout>/Cargo.toml

# Live realtime ratio, per checkout (lifted, real window, real cached small model):
cargo build --release -p humm-gui --manifest-path <checkout>/Cargo.toml
HUMM_DATA_DIR=<tmp>/data HUMM_CONFIG_DIR=<tmp>/config HUMM_LOG_DIR=<tmp>/logs \
HUMM_SMOKE_LIVE_FIXTURE=/Users/jawad/RustroverProjects/buzz/testdata/audio-long.mp3 \
HUMM_SMOKE_LIVE_SECONDS=200 \
  caffeinate -dimsu <checkout>/target/release/humm-gui
# ratio:  grep -A2 measured_speed <tmp>/config/settings.toml
# states: grep -c "whisper_init_state: compute buffer (decode)" <tmp>/logs/logs.txt
```

`caffeinate -dimsu` and activating the window are not optional for the live
runs — see §4.2's harness note and `docs/gui-manual/M7.md` §10.3.
