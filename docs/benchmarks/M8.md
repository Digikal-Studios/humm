# M8 Benchmark Comparison & Acceptance (Task 16)

Per `CLAUDE.md`'s regression rule and the standing lesson `docs/benchmarks/M5.md`
§1.2 established and repeated by M6/M7: **re-baseline against a same-day
checkout of the previous milestone's tip, never against recorded numbers, and
interleave the pairs so both checkouts face the same contention.** All runs
2026-07-27, sandbox-lifted (Metal), Apple M4 (Mac16,12) / 32 GiB / macOS
26.5.2 (25F84) — same machine as M1–M7.

M7 = `git worktree add .claude/worktrees/m8-bench-m7 5e70790` (M7's close
commit, tagged `docs/benchmarks/M7.md`), its own `target/`, seeded from this
worktree's `.cargo-home` (`cargo fetch` needed no new downloads — the M8
crates' extra deps, e.g. `humm-dfn`/`humm-diarize`'s, are simply unused by
the M7 checkout). M8 = this branch's tip (`191081d`). Binaries verified
distinct (`md5` of the `e2e`/`decode`/`export`/`humm` executables all differ
between checkouts), so the two checkouts really were compiled separately.

## 0. Conditions, stated up front — an unusually hostile window

This machine carried real, un-pausable, and *unusually heavy* external load
for the entire benching window — `uptime` load averages climbed from **19 to
106** over the course of the session (vs M7's 4.3–9.7, M6's 10–19), driven by
an unrelated parallel `cargo build` (another project's `bevy_reflect`
compile, confirmed via `ps aux`) that was not this session's to stop. This is
the busiest machine condition of any milestone's benching session to date.
Every comparison below is **paired and interleaved**, alternating which
checkout runs first, specifically because absolute numbers this session are
even less informative in isolation than usual — several individual
measurements below swing by 30–70% pair-to-pair on **provably byte-identical
code** (§3.2), which is the load, not a regression, and is reported plainly
rather than smoothed over.

## 1. Call-path innocence (`git diff 5e70790..HEAD`) — done first, before any bench

Per the task brief, this is the code-reading half; Task 4's
`hooks_never_run_when_deps_none` test pins the corresponding behavior.
Every hunk on the three named files, classified:

### 1.1 `crates/humm-whisper/src/engine.rs` — identical (visibility only)

The entire diff is two `fn` → `pub(crate) fn` visibility changes
(`init_logging`, `default_threads`) plus doc comments explaining *why*
(`crate::langdetect::WhisperLangDetector`, F-114, now shares them). **Zero
executable-logic changes.** The `impl TranscriptionEngine` block the `e2e`
bench calls (`WhisperEngine::transcribe`) is untouched, byte-for-byte,
between the two checkouts.

### 1.2 `crates/humm-media/src/decode.rs` — moved, not changed (behavior-preserving refactor)

`AudioDecoder::decode` (the trait method both the `e2e` and `decode` benches
call) is now a one-line wrapper: `self.decode_mono_at(path, SAMPLE_RATE,
cancel)`. `decode_mono_at` is the old `decode` body, generalized to take a
`sample_rate` parameter (needed by `humm-dfn`'s 48 kHz DeepFilterNet3 pass,
F-112) — with `SAMPLE_RATE` (`= 16_000`, `humm_core::boundary::SAMPLE_RATE`)
passed in, the ffmpeg command built is **the exact same arguments**
(`-ar 16000` either way), same read loop, same `bytes_to_f32`. A new test
(`decode_delegates_to_decode_mono_at_16k`) pins the delegation. `map_spawn_error`
gained one extra string argument (an install hint) — cosmetic, off the hot
path (only reached on ffmpeg-missing). **Classification: moved — zero
behavioral change on the path either bench exercises.**

### 1.3 `crates/humm-core/src/pipeline.rs` — new-branch-not-taken (on the default path)

`run_file_job` gained two new parameters: `audio_input: &Path` (M8's
pre-transcription-chain decode target) and `language_override: Option<Language>`
(F-114's detected language). Traced through with the default-path values the
queue actually passes (§1.4): `audio_input == &job.input`,
`language_override == None`.

- `audio_input.exists()`/`prober.probe(audio_input)`/`decoder.decode(audio_input, ..)`
  — identical to the old `job.input`-keyed calls, since `audio_input` *is*
  `job.input`'s clone on this path.
- `let language = language_override.or(job.options.language);` — with
  `language_override: None`, this evaluates to exactly `job.options.language`,
  the old value. One extra `Option::or` call, no allocation.
- `output_file_path(&job.input, .., language, ..)` and
  `apply_source_disposition(.., &job.input, ..)` are unconditionally keyed on
  `job.input`, never `audio_input` — unchanged.
- Not on this bench's path at all (the `e2e`/`decode` benches call the
  decoder/engine directly, bypassing `run_file_job` and the queue entirely —
  confirmed by reading `crates/humm-whisper/benches/e2e.rs`), but is on the
  *product's* file-task path, so documented here per the task brief.
- **Classification: new-branch-not-taken** — the two new parameters widen
  the signature but produce the prior values on the default (no pre-chain)
  invocation; a new test
  (`run_file_job_decodes_audio_input_not_job_input`) pins the
  `audio_input`-vs-`job.input` distinction directly.

### 1.4 `crates/humm-core/src/queue.rs` — new-branch-not-taken, gated on `Option`/`bool`

`Runner::run_job` gained a fixed-order isolation → noise-reduction →
language-detection block between `check_skip` and artifact-ensure. Traced
with the CLI's actual default wiring (`crates/humm-cli/src/run.rs:284-323`)
and no flags passed (the default invocation §2.2 actually runs):

**Correction (post-review): `postproc_cfg` is not `None` on the CLI.**
An earlier draft of this section claimed `postproc_cfg.as_ref()` short-circuits
because no `PostprocConfigSource` is wired — that is wrong. `run.rs:309-311`
always wires `postproc: Some(Arc::new(CliPostprocSource { .. }))`, so
`postproc_cfg` at `queue.rs:1330` is `Some(real config)` on every CLI
invocation, `check_skip`-hook included. The actual default-off mechanism is
two separate layers, neither of which is "no config source":

- **Isolation** (`extract_speech`): gated purely on the *task's own* option,
  not on `postproc_cfg` at all — `if job.options.extract_speech && let
  Some(isolator) = self.isolator.clone()`. The CLI's `-e` flag defaults
  `false` (unset here), so `&&` short-circuits on the first operand;
  `isolator.clone()`/`isolate()` are never reached, even though `isolator`
  is always `Some(DemucsIsolator::new())` on the CLI. One `bool` read.
- **Noise reduction / language detection**: gated on
  `cfg.noise_reduction.enabled`/`cfg.language_detection.enabled` — real
  fields read from a real `Some(cfg)`, both defaulting to `false`
  (`crates/humm-core/src/settings.rs:558` `NoiseReductionSettings::enabled`
  doc: "Buzz plugins default to disabled"; `:580`
  `LangDetectSettings::enabled`, same doc, explicit `Default` impl). This
  default is **universal, not CLI-specific** — the GUI wires real
  `reducer`/`lang_detector` adapters too and stays off through this same
  settings default, not through an absent adapter.
  On the CLI *specifically*, there is also a second, redundant gate:
  `reducer`/`lang_detector` are hardcoded `None` in `RunnerDeps`
  (`run.rs:322-323`) regardless of settings, so `&& let Some(reducer) = ..`/
  `&& let Some(detector) = ..` short-circuit there too. Either gate alone
  is sufficient on the CLI; the settings gate is what the GUI relies on
  alone.
- The pin test `hooks_never_run_when_deps_none` (`queue.rs:6562`) proves the
  **adapter-absence** half specifically: it sets both `enabled: true` *and*
  `extract_speech = true`, but keeps `isolator`/`reducer`/`lang_detector`
  all `None`, and asserts no hook ran — i.e. it is not evidence that
  settings default to disabled (they're forced `true` in this test), it is
  evidence that an absent adapter is independently sufficient to suppress
  the hook even when every flag says "on".
- Three new `token.is_canceled()` checks (one per stage boundary) — cheap
  atomic loads, same cost class as the existing checks this function already
  had.
- `TempAudioGuard { isolated: None, denoised: None, keep_denoised: false }`
  is constructed unconditionally (one small struct literal, no heap
  allocation) and dropped at the end of `run_job`; its `Drop` impl does two
  `Option::take()`s that both resolve to `None` on this path — no
  filesystem I/O.
- `audio_input = job.input.clone()` — one unconditional `PathBuf` clone per
  task (not per segment, not per chunk) — the same cost class M7.md's own
  §2.1 accepted for M7's `Box<PostCompleteContext>` addition.
- `run_file_job(&job, &audio_input, detected_language, ..)` — `detected_language`
  is `None` on this path, matching §1.3's traced-through result.
  `PostCompleteContext` gained one `detected_language: Option<Language>`
  field (cheap `Copy`).
- `ensure_artifacts`'s progress-callback closure was factored into a shared
  `model_download_progress_fn` (reused by the new
  `ensure_tiny_lang_detect_model`) — same callback body, same throttle,
  purely a refactor for reuse; the artifact-ensure call site itself is
  unchanged.
- The remaining ~1,500 of the diff's ~1,700 lines are new `#[cfg(test)]`
  tests (the last hunk alone is a single `+1035`-line block appended to the
  `mod tests` block) and the new isolation/reduction/detection
  implementations themselves, none of which execute when their respective
  gates are off.
- **Classification: new-branch-not-taken** — every new code path added this
  milestone is behind an `Option::None` or `bool: false` check that the
  CLI's actual default wiring satisfies; the only unconditional additions
  are the cost class M7.md's own precedent already accepted (one clone, a
  few bool/atomic checks, one small `Drop`-guarded struct).

### 1.5 Verdict

**No hot-path change that runs by default.** Every hunk across the three
files is either byte-identical logic (engine.rs), a behavior-preserving
refactor with a pinning test (decode.rs), or gated behind an `Option`/`bool`
check the default invocation (no `-e`; a real but hooks-all-disabled
`postproc` config, §1.4's correction) takes the "off" branch of. Not
BLOCKED.

## 2. Transcription-path regression guard (the blocking gate)

Two independent measurements this milestone, because M8's actual new surface
(the queue's pre-transcription chain, §1.4) sits **outside** the criterion
`e2e` bench's call path entirely (it calls the decoder/engine directly,
bypassing `Runner::run_job`/`run_file_job`) — so the historically-tracked
criterion number alone would not exercise M8's real additions at all. §2.1 is
the same bench M1–M7 tracked (continuity with the existing gate); §2.2 is a
real product-path (`humm add`) run with the real cached `small` model against
Buzz's `audio-long.mp3`, which *does* go through `Runner::run_job`.

### 2.1 `e2e/decode_transcribe/whisper-french.mp3/tiny` (criterion, the tracked gate)

Real `tiny` GGML model (GPU/Metal), Buzz's `whisper-french.mp3`, criterion
10-sample runs — identical configuration to M1–M7. Four interleaved pairs
(a fourth was added after pair A's outlier, following the M7.md §3.2
precedent of adding pairs when a reading looks off):

| Pair | Order | M7 mean (CI) | M8 mean (CI) | Δ (M8 vs M7) |
|---|---|---|---|---|
| A | M7→M8 | 530.71 ms [513.98, 550.74] | 400.75 ms [390.80, 417.44] | **−24.5 %** |
| B | M8→M7 | 397.85 ms [388.45, 403.93] | 385.74 ms [381.14, 390.46] | **−3.0 %** |
| C | M7→M8 | 401.71 ms [399.55, 403.77] | 430.47 ms [422.62, 434.89] | **+7.2 %** |
| D | M7→M8 | 410.05 ms [397.68, 423.60] | 417.81 ms [405.26, 439.94] | **+1.9 %** |

Pair A's M7 run (530.71 ms) is a clear outlier against its own subsequent
runs (397.85/401.71/410.05 ms) — the load average happened to roughly double
(51→102) between that pair's two runs; its `[513.98, 550.74]` interval
overlaps none of the other seven in this table, which is exactly why it's
flagged rather than blended in. Pooled over all four pairs: **M7 435.08 ms,
M8 408.69 ms (−6.1 %)**; excluding pair A's outlier (pairs B–D only): **M7
403.20 ms, M8 411.34 ms (+2.0 %)**. Either way the sign of the delta flips
across pairs; restricted to pairs B–D (checked pairwise, not just by eye),
every one of the six CIs overlaps at least one other — the M7.md §2
signature of noise, not a regression.

### 2.2 Real product-path run: `humm add` on `audio-long.mp3`, `small` model

The CLI's own default invocation (`humm add <file> --srt`, default
`--model-size small`, no `-e` flag, and the CLI has no flag for the
noise-reduction/language-detection hooks at all — those come only from
`settings.toml`, both `enabled: false` by default — i.e. exactly the
call-path-innocent default traced in §1.4), Buzz's `audio-long.mp3` (120.0 s,
`ffprobe`-confirmed), the real cached `small` model
(`~/Library/Application Support/humm/models/ggml-small.bin` +
`ggml-small-encoder.mlmodelc`), isolated `HUMM_DATA_DIR`/`HUMM_CONFIG_DIR`/
`HUMM_LOG_DIR`/output directory per run, wall-clock timed. This genuinely
exercises `Runner::run_job` → `run_file_job`, unlike §2.1. Five interleaved
pairs (added beyond the usual three because the swings were large enough to
want more data before trusting a pooled number):

| Pair | Order | M7 | M8 | Δ (M8 vs M7) |
|---|---|---|---|---|
| A | M7→M8 | 25.657 s | 38.116 s | +48.6 % |
| B | M8→M7 | 18.408 s | 21.101 s | +14.6 % |
| C | M8→M7 | 25.016 s | 15.941 s | −36.3 % |
| D | M7→M8 | 18.459 s | 25.548 s | +38.4 % |
| E | M8→M7 | 25.080 s | 18.362 s | −26.8 % |

Load averages ranged 33–75 across these five pairs (no quiet control
available this session). **Pooled: M7 22.524 s, M8 23.814 s (+5.7 %) — but
individual pairs swing as wide as +48.6 % (A) and −36.3 % (C), so this
pooled figure is not a precise estimate of anything; it is five noisy
single-shot samples averaged together, not a criterion-grade statistic.**
The sign flips three times across five pairs with no order correlation (M8 ran
slower in A/B/D regardless of running first or second, faster in C/E) —
this is single-shot wall-clock timing on a heavily and unevenly loaded
machine, not a stable signal; a 120 s real file with sample size 1 has no
internal CI the way criterion's 10-sample `e2e` does, so this table is
weaker evidence than §2.1 by construction and is reported as corroborating,
not as the primary gate metric.

### 2.3 Verdict

**No transcription-path regression. Gate: PASS.** Two independent lines of
evidence, both negative for a regression:

- **Code**: §1 found no hot-path change that executes by default — the
  criterion bench's own call path (decoder + engine) is untouched
  byte-for-byte; the product path's (queue+pipeline) only unconditional
  additions are one `PathBuf` clone and a handful of cheap `bool`/`Option`
  checks per **task** (not per chunk), the same cost class M7's own
  `Box<PostCompleteContext>` addition was.
- **Measurement**: both §2.1 and §2.2 show the sign of the M7-vs-M8 delta
  flipping pair-to-pair, under a session that was measurably the noisiest
  of any milestone to date (load 19–106 vs M7's 4.3–9.7). §2.1's pairs B–D
  additionally overlap pairwise (pair A's M7 reading is the flagged
  outlier, excluded from that check); §2.2 has no per-run CI to check
  overlap against at all (single-shot wall clock), so its sign-flip alone,
  not overlap, is what it contributes. Neither table shows a consistent,
  one-directional slowdown for M8.

## 3. Supporting benches

`CLAUDE.md`'s own Commands section and the task brief both name a
"decode/resample/export" criterion suite; there is no `resample` bench
target anywhere in this workspace (`find crates -path '*/benches/*.rs'`
lists exactly `export.rs`, `table_scroll.rs`, `viewer_scroll.rs`,
`decode.rs`, `e2e.rs` — five files, none named `resample`). This is
unchanged from M7 — resampling is exercised only as part of `decode`'s own
ffmpeg `-ar` conversion, never as a standalone bench — so "decode/resample"
is read here as one bench (`decode`), same as every prior milestone's own
benching docs did.

underlying code is untouched, which it is here — §1.2):

## 4. Reproducing

```bash
export CARGO_HOME="$(git rev-parse --show-toplevel)/.cargo-home"
git worktree add /path/to/m8-bench-m7 5e70790      # same-day M7 checkout

# Interleaved criterion pairs (lifted; alternate order between pairs):
cargo bench -p humm-whisper --bench e2e    --manifest-path <checkout>/Cargo.toml
cargo bench -p humm-media   --bench decode --manifest-path <checkout>/Cargo.toml
cargo bench -p humm-core    --bench export --manifest-path <checkout>/Cargo.toml

# Real product-path run, per checkout (lifted, real cached small model,
# Buzz's audio-long.mp3, isolated HUMM_* dirs per run):
cargo build --release -p humm-cli --manifest-path <checkout>/Cargo.toml
HUMM_DATA_DIR=<tmp>/data HUMM_CONFIG_DIR=<tmp>/config HUMM_LOG_DIR=<tmp>/logs \
  <checkout>/target/release/humm add \
  /Users/jawad/RustroverProjects/buzz/testdata/audio-long.mp3 \
  --srt -d <tmp>/out --quiet
# time via wall clock (date +%s.%N before/after, or `time`)
```

`dangerouslyDisableSandbox`/an equivalent sandbox lift is not optional for
any run above — the sandboxed shell segfaults inside ggml's Metal allocator
on GPU model load, the same M1–M7 precedent.
