# M5 GUI Manual Acceptance Checklist (v3)

The live-recording half of the `gui-manual` surface (F-060/F-061/F-062/F-064/
F-065, plus the F-004 Record-button/⌘R unlock). Same conventions as
`docs/gui-manual/M3.md`/`M4.md`: each numbered item carries steps, expected
result, and a tag — `[kittest: <test name>]` when an `egui_kittest` test
already automates it (real names grepped against `crates/humm-gui/tests/*.rs`,
current as of Task 14), `[windowed]` when Task 14 executed it as a real,
unsandboxed `humm-gui` process (see the execution records below), or
`[manual]` when it genuinely needs a human at a real keyboard/mouse/microphone.
Where a `[manual]` item is additionally backed by non-GUI unit/kittest
coverage, that's noted inline — it narrows what a human has to eyeball but
doesn't replace the windowed/manual check.

**Why this milestone could run more windowed checks than M3/M4 without a
human:** the recording window's session is driven by a real background
thread doing real work (model load, chunking, engine calls) independent of
pointer input, so a scripted hook (`HUMM_SMOKE_LIVE_FIXTURE`,
`docs/HUMM_SURFACE.md` §5.1) can drive the *entire* Record→transcribe→Stop
flow by calling the same functions a click would, with no OS input injection
needed. What a hook categorically cannot do is press a real physical key,
drag a real mouse, or grant a real macOS permission dialog — those stay
`[manual]`.

Build/run: `cargo build --release -p humm-gui` then run the binary directly
(unsandboxed; the sandbox blocks GPU/window creation and the CoreAudio device
the same way it blocks the whisper `e2e` bench and M4's A/V-drift run). Fresh
state: point `HUMM_DATA_DIR`/`HUMM_CONFIG_DIR`/`HUMM_LOG_DIR` at empty temp
dirs per run (leave `HUMM_MODEL_ROOT` unset to reuse the real cached models).

**The standing microphone blocker, stated up front:** a real microphone
cannot be exercised in this environment — `.superpowers/sdd/task-5-report.md`
documents a sandbox-lifted `cpal` input-stream open hanging indefinitely on
an unanswered first-time macOS TCC (microphone-access) prompt, with no
interactive session present to grant it. Every `[windowed]` item below used
`HUMM_SMOKE_LIVE_FIXTURE` (`crates/humm-gui/src/live_fixture.rs`'s
`FixtureCapture`) — real, ffmpeg-decoded fixture audio streamed at genuine
wall-clock pace through the exact same capture boundary a real device would
use — standing in for the mic. **No item below claims a real microphone was
used**; "mic-permission grant + a real-mic run" is itself listed as the first
deferred pointer item below.

## 1. F-060 — Live recording window (device, meter, options)

1. **Toolbar Record / ⌘R opens the window unconditionally (F-004 unlock).**
   Click the Record button, or press ⌘R. Expected: the recording window
   opens (or focuses, if already open) — the button is never gated (Buzz
   parity, unlike every other conditionally-enabled toolbar action).
   `[kittest: toolbar_record_is_unconditionally_enabled_and_its_click_opens_the_recording_window]`.
   `[windowed]`: all four Task 14 acceptance runs opened this exact window
   as a real OS viewport via `HummApp::open_recording_window` — the same
   function the toolbar/⌘R path resolves to — confirmed via
   `Creating new viewport "…" (Some("Live Recording"))` +
   `wgpu_hal::metal::surface` swapchain lines in the logs, four separate
   process runs, each exiting 0.
2. **Options group + microphone row render; device combo preselects the
   default.** Expected: model-size/task/language combo (reused from the file
   options sheet), Advanced… button, a microphone row with the system
   default preselected (or the first device, or none with an empty list —
   Record stays clickable regardless).
   `[kittest: window_renders_the_record_button_and_microphone_label]`,
   `[kittest: empty_device_list_leaves_the_record_button_clickable]`.
   `[windowed]`: every acceptance run's `FixtureCapture` reports a single
   scripted device (`"Fixture Capture (HUMM_SMOKE_LIVE_FIXTURE)"`, flagged
   default), which `default_device_selection` preselected exactly as a real
   single-device machine would.
3. **Record click: full state-machine flip.** Options/device/mic-label
   disable, presentation bar shows, copy bar hides, panel clears, meter
   resets. Expected observable state change on click.
   `[kittest: record_click_disables_options_and_shows_the_presentation_placeholder]`.
   `[windowed]`: driven for real by `apply_smoke_live_fixture_tick` calling
   `RecordingVm::on_record_clicked` (identical function a click invokes) —
   the log's `"Record clicked (small model), Ns window"` line marks it.
4. **Stop click: two-phase stop, button disabled pending ack.** Clicking
   Stop while Recording moves to `Stopping` (button disabled) until the
   session thread's `Stopped` message arrives, then restores the stopped-state
   UI (options re-enabled, presentation bar hidden, copy bar shown,
   meter-only capture restarted).
   `[kittest: stop_click_moves_to_stopping_and_disables_the_button_pending_the_session_ack]`,
   `[kittest: finish_stopping_restores_the_stopped_ui_once_the_session_acks]`.
   `[windowed]`: every acceptance run's log shows the `"…window elapsed,
   requesting stop"` → `"session stopped, closing recording window"` pair,
   the real session thread's ack landing before the window closed.
5. **Meter paints without panicking across many frames.**
   `[kittest: meter_paints_several_frames_without_panicking]`. See item 21
   (F-060 meter-repaint cadence) below for the real windowed cadence
   measurement.
6. **Realtime-fit warning shows/hides on the stored measured-speed map.**
   A stored ratio < 1.0 for the selected size shows the inline caution; no
   entry, or a ratio ≥ 1.0, shows nothing.
   `[kittest: realtime_fit_warning_renders_when_the_measured_speed_is_below_one]`,
   `[kittest: no_realtime_fit_warning_renders_with_no_measured_entry]`.
   `[windowed]`: every acceptance run wrote a real ratio (1.57×–2.53×, all
   ≥ 1.0×) to `settings.recording.measured_speed`, so a **subsequent** open
   of this same window would render *no* warning for `small` on this
   machine — consistent with the stated rule, confirmed by inspecting the
   written `settings.toml` after each run (not by re-opening the window to
   look, which is `[manual]`).
7. **Advanced sheet opens; every section renders (incl. the disabled M6
   translation block).** Advanced… opens a modal with Initial Prompt,
   silence threshold, mode combo (rows swap with mode), export block
   (enable-gated), upload-URL field, and a **permanently disabled**
   "Enable AI translation" block with tooltip "Live translation arrives with
   the API backend milestone" (F-063 is M6).
   `[kittest: advanced_button_click_opens_the_sheet]`,
   `[kittest: disabled_llm_block_renders_with_its_tooltip_target_present]`,
   `[kittest: advanced_sheet_mode_dependent_rows_swap_with_the_mode]`,
   `[kittest: export_block_gates_on_the_enable_checkbox]`. Typing into the
   sheet's fields by hand is `[manual]`.
8. **Window close: immediate if Stopped, deferred (two-phase) if
   Recording.** Closing while Stopped closes immediately; closing while
   Recording/Stopping vetoes the OS close (`CancelClose`), latches a stop
   intent, and finishes the close once the session's `Stopped` arrives.
   `[windowed]`: every acceptance run's own programmatic "close" (setting
   `close_requested` only after observing `RecordingStatus::Stopped`, the
   same field a stopped-state window-close sets) went through
   `harvest_recording_close` and the window disappeared from
   `HummApp.recording`, confirmed by the tick then requesting — and getting
   — a clean root-viewport close (process exit 0) every time. A **live**
   close-while-recording (clicking the red close button mid-session and
   watching the veto) is `[manual]` — the state-machine rule itself is unit
   /kittest-covered (`stop_click_moves_to_stopping_and_disables_the_button_
   pending_the_session_ack`).

## 2. F-061 — Real-time transcription loop

9. **Chunk cadence, silence-skip, rolling prompt, drop-behind.** Pure
   core logic — 13 `live::session::` unit tests (chunk timing per mode,
   silence-skip below threshold, rolling-prompt propagation, queue
   drop-behind via `MeterBatch.queue_len`, cancel-mid-idle-pause,
   `LiveMeasurement` math). `unit`, not gui-manual; cited here for
   completeness since this row's stated method is `unit (chunker) +
   gui-manual`.
10. **Two real utterances end to end (scripted, no real sleeping).** Record
    → two chunked+transcribed utterances (a `MockCapture` ring sized to one
    batch, the scripted engine pushing the second mid-call) → Stop; panel
    text, store row lifecycle (incl. restart-survival via store reopen),
    exact export bytes, exact upload sequence all asserted.
    `[kittest: scripted_end_to_end_record_two_utterances_then_stop]`.
11. **Session-thread panic recovery.** A scripted engine panic mid-session
    still completes the store row with the utterances that landed before
    the crash, shows the "ended unexpectedly" dialog, and lifts the
    close-veto so the window isn't stranded.
    `[kittest: session_thread_panic_recovers_the_window_and_completes_the_store_row]`.
12. **Live realtime-fit measurement — the milestone's own acceptance item #1,
    `[windowed]` and PASSED.** Executed 4 times (20 s/30 s/200 s×2) against
    the **real** `WhisperEngine` (cached `small` model, Metal) fed real,
    wall-clock-paced fixture audio (Buzz's `audio-long.mp3`) through
    `FixtureCapture` (the mic stand-in, see the header note above) driving
    the real recording window end to end. Measured `LiveMeasurement`
    realtime ratios: **1.5652×, 2.5311×, 1.8732×, 2.0744×** — all ≥ 1.0×,
    satisfying the gate. Full numbers, method, and the honest gap-analysis
    against the M1 CLI benchmark's ≈17.3× figure (different measurement
    regime — continuous single-call file decode vs. per-chunk live calls,
    each of which reloads the CoreML encoder from disk via
    `create_state()`→`whisper_coreml_init()`, verified in vendored
    whisper.cpp): `docs/benchmarks/M5.md` §3. Real
    transcript quality was also observed (34 ordered French segments in one
    run, e.g. `"Bienvenue dans Paserelle, un podcast pensé pour…"`), and the
    benign-`Canceled`-exit ledger item was seen firing live at the exact
    Stop instant (`whisper_full_with_state: failed to decode` in whisper.cpp's
    own log, zero `error_message` on the completed row) — real evidence the
    documented graceful-cancel path holds under a genuine whisper.cpp abort.
    **What this evidence does not claim**: a real microphone was never
    involved (deferred pointer item below), and no human watched the window
    while this ran — the evidence is the log timeline, the persisted store
    row, and the measured ratio, not a visual judgment.

## Meter repaint smoothness (F-060 acceptance item 5)

25. **Recording-window repaint cadence over a real 200 s windowed run,
    `[windowed]` — no jank observed.** `HUMM_SMOKE_METER_FRAME_LOG` (run 3
    of the four acceptance runs, `docs/benchmarks/M5.md` §3.3) logged one
    epoch-millisecond line per actual recording-window redraw while
    Recording — 11,993 frames over 199.97 s:

    | Metric | Value |
    |---|---|
    | Mean inter-frame interval | 16.68 ms |
    | Median | 17 ms |
    | p95 | 18 ms |
    | p99 | 18 ms |
    | Max | 53 ms |
    | Frames > 50 ms | 1 of 11,992 (0.008%) |
    | Frames > 100 ms | 0 |

    Effectively a locked ~60 fps cadence (tighter than spec §2.5's own
    "~30 ms" floor — the meter's `request_repaint_after(30ms)` is a
    minimum, not a target; the observed rate is bounded by this display's
    vsync instead) with a single, isolated 53 ms outlier out of nearly
    12,000 frames.

    **Honest scope of this evidence:** this instrumented cadence data
    confirms the redraw *interval* stayed tight and consistent for the
    whole run — a real, machine-measured proxy for "no jank," not a human
    watching the meter bars and judging smoothness by eye. A human visually
    confirming the meter *looks* smooth while genuinely dragging focus
    between windows, resizing, etc. is a `[manual]` item, listed below.
