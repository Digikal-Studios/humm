# M3 GUI Manual Acceptance Checklist (v1)

One numbered item per M3 `gui-manual` behavior (`docs/analysis/PARITY_MATRIX.md`'s
verification-method column). Each item: steps, expected result, and a tag —
`[kittest: <test name>]` when an `egui_kittest` test already automates it
(grepped for real names against `crates/humm-gui/tests/*.rs`, current as of
Task 12), or `[manual]` when it genuinely needs a real windowed run (no
display in this sandboxed dev environment — every `[manual]` item here is
**pending Task 13**, executed on an unsandboxed machine with a display).
Where a `[manual]` item is additionally backed by non-GUI unit-test coverage
(the underlying logic, not the window), that's noted inline — it narrows what
Task 13 actually has to eyeball, but doesn't replace the windowed check.

Build/run: `cargo run -p humm-gui` (unsandboxed; sandbox blocks GPU/window
creation the same way it blocks the whisper e2e bench). Fresh state: point
`HUMM_DATA_DIR`/`HUMM_CONFIG_DIR` at an empty temp directory per run unless a
specific item says otherwise.
