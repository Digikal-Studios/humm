# M4 GUI Manual Acceptance Checklist (v2)

The transcript-viewer half of the `gui-manual` surface (F-080..F-086, plus the
F-003/F-004 open-path unlock). Same conventions as `docs/gui-manual/M3.md`:
each numbered item carries steps, expected result, and a tag —
`[kittest: <test name>]` when an `egui_kittest` test already automates it
(real names grepped against `crates/humm-gui/tests/*.rs`, current as of Task
14), or `[manual]` when it genuinely needs a real windowed run with pointer
input. Where a `[manual]` item is additionally backed by non-GUI unit-test
coverage, that's noted inline — it narrows what a human has to eyeball but
doesn't replace the windowed check.

**Why so many `[manual]`s remain the same shape as M3's:** the viewer window is
a deferred egui viewport, which `egui_kittest`'s single-root-viewport `Harness`
cannot reach into (identical to M3's About/Preferences immediate viewports). So
every viewer test drives the extracted plain render fn `views::viewer::viewer_ui`
(and the pure `ViewerVm`/`viewer_table`/`viewer_search`/`playback_controls`/
`export_menu`/`resizer` seams) directly over a bare `egui::Ui` — proving the
logic end to end without window plumbing. What still needs a real screen is the
window plumbing itself (a second OS viewport, native save dialogs, pointer
drag on the splitter/scrubber, multi-window focus) plus genuinely live playback
(a real audio device + real ffmpeg video frames). The A/V-drift portion of that
*is* now executed windowed via the `HUMM_SMOKE_OPEN_VIEWER` hook — see the
execution record at the bottom.

Build/run: `cargo run -p humm-gui` (unsandboxed; the sandbox blocks GPU/window
creation and the CoreAudio device the same way it blocks the whisper e2e
bench). Fresh state: point `HUMM_DATA_DIR`/`HUMM_CONFIG_DIR`/`HUMM_MODEL_ROOT`/
`HUMM_LOG_DIR` at empty temp dirs per run.

## 1. F-080 — Viewer window (open paths, view modes, layout)

1. **Open from the table gates to Completed/Skipped on every path.** Select a
   completed row and press Return; double-click a completed row; select
   completed row(s) and click Open Transcript. Expected: a viewer window opens
   for each; a non-completed selection is a silent no-op on all three paths
   (Buzz's Return-bypass deliberately not ported — ledger #13). The gate rule
   (`toolbar_enablement.open` = non-empty, all-openable selection) and the
   `can_open(status)` matrix are unit-tested; the actual window opening in a
   real OS viewport is `[manual]` (executed windowed via the A/V-drift run
   below, which opens the viewer through the exact `open_viewer` path).
   `[manual]` + unit (`viewer::can_open` matrix, `toolbar_enablement.open`).
2. **View-mode switches (Timestamps / Text / Translation).** Click the View
   button → Text (⌘E), Translation (⌘L), Timestamps (⌘T). Expected: Timestamps
   shows the editor table + player; Text shows read-only paragraph-joined text
   (`"\n\n"` at gaps ≥ `HUMM_PARAGRAPH_SPLIT_TIME`); Translation shows
   space-joined translations with no paragraph split (Buzz quirk).
   `[kittest: timestamps_mode_shows_segment_table_placeholder_rows]`,
   `[kittest: text_mode_shows_paragraph_joined_text]`. Live pointer clicks on
   the menu are `[manual]`.
3. **Translation mode/column/export entries hidden without translations.**
   Open a transcript with no translations. Expected: the Translation view-menu
   entry, the table's Translation column, and the Export menu's Translation
   half are all absent; they appear the moment a translation cell edit lands
   (micro-✚, ledger #7).
   `[kittest: translation_menu_entry_hidden_without_translations]`,
   `[kittest: translation_entries_hidden_without_translations]`.
4. **Empty transcript shows the explanatory empty state.** Open a
   Completed/Skipped transcript with zero segments. Expected: a "No segments —
   the input may be silence-only" label, no crash; the player/toolbar still
   work. `[kittest: empty_transcript_shows_explanatory_state]`.
5. **Same-transcript re-open focuses the live window (no duplicate).** With a
   viewer open for a transcript, open it again. Expected: the existing window is
   focused (`ViewportCommand::Focus`), not duplicated (ledger #1). The
   focus-vs-duplicate decision (`open_viewer` finds the live entry and sets
   `focus_requested`) is exercised by the app-level open seam; the actual
   second-window-doesn't-appear + focus-raise is `[manual]` (needs two real
   viewports).
6. **Shared geometry persists, last-close-wins.** Resize a viewer, close it,
   open another. Expected: the new window opens at the persisted
   `settings.viewer.geometry` (min 800×500, default 1000×800); geometry is
   captured per-VM at open so a closing window never re-snaps other open ones.
   `[manual]` (real viewport geometry round-trip; the per-VM capture logic is
   in `app.rs::persist_viewer_geometry_if_changed`).
7. **Splitter drag persists per media kind.** Drag the table/media handle in an
   audio viewer, then in a video viewer. Expected: each kind's fraction
   (`audio_splitter_fraction` 0.95 / `video_splitter_fraction` 0.8 defaults)
   persists independently. `[manual]` (pointer drag on a hand-rolled splitter;
   the fraction clamp/persist logic is unit-covered).

## 2. F-003 / F-004 — Open-path unlock

8. **Return / double-click / Open Transcript now open the viewer (the M4
   unlock).** Previously these emitted `OpenSelected` into an app.rs no-op.
   Expected: all three now open/focus the viewer, each gated to
   Completed/Skipped; the old "arrives in the next milestone" Open-Transcript
   tooltip is retired for the selection-rule text. The enablement matrix is
   `[kittest]` (M3's `toolbar_*` tests in `kittest_actions.rs`); the open action
   wiring is `[manual]` (windowed), exercised via the A/V-drift run below.

## 3. F-081 — Segment editing

9. **Begin editing (double-click cell / Return on selected row).** Expected: a
   double-click on a cell or Return on the selected row (its Start cell) opens a
   single inline editor; only the edited cell becomes a `TextEdit`, every other
   cell stays a label (so 100k rows stay smooth).
   `[kittest: table_renders_100k_rows_without_panic]` (100k render);
   double-click/Return begin is `[manual]` (the begin logic is unit-tested).
10. **Timestamp edit: filter, nudge, commit, revert.** Edit a Start/End cell:
    type only `[0-9:.]`; press `+`/`-` to nudge the typed buffer ±500 ms
    (floored at 0 — note the nudge bases on the *typed buffer*, ledger #14);
    commit on Enter/Tab/focus-out; type garbage → reverts silently. Nudge/parse
    rules are unit-tested (`nudge_buffer_ms` add/sub/floor/garbage, timestamp
    parse round-trip). Live typing is `[manual]`.
11. **Commit validation: reject + neighbor clamp.** Set a Start ≥ its End →
    rejected (no-op); set a Start < prev.End → prev.End is pulled back to it
    (both rows written); symmetric for End vs next.Start. Both rows persist.
    `[kittest: edit_survives_reopen]` (a commit through the seam survives a
    fresh `ViewerVm::open`); the clamp matrix is unit-tested
    (`apply_timestamp_edit_writes_value_and_clamped_neighbor_to_store`).
12. **Text/Translation edit: multi-line, Esc commits.** Edit a Text cell;
    Enter, Tab, **and Esc** all commit (Esc-commits is ledger #6); a non-blank
    Translation edit unhides the Translation column/menu/export.
    `[kittest: esc_commits_text_edit]`,
    `[kittest: translation_entries_hidden_without_translations]` (unhide).
13. **Nudge shortcuts on the selected row.** ⌘←/⌘→ nudge Start ∓/±500 ms,
    ⌘⇧←/⌘⇧→ nudge End, reading fresh current values; loop range refreshes if
    looping. Unit-tested (`nudge_uses_fresh_values_after_prior_edit`,
    floor-zero, no-selection no-op). Live keypress in a real viewport is
    `[manual]`.
14. **Instant persist + autosave indicator; edits survive restart.** Every
    commit writes the store synchronously and flashes "edited · saved"
    (`saved_flash`, ~1.5 s); a store-write failure keeps the memory edit and
    raises an inline unsaved banner (ADR-018). Restarting the app and reopening
    the transcript shows the edit.
    `[kittest: edit_survives_reopen]` (the automated half of "edits survive
    restart" — commit via seam, re-`ViewerVm::open` the same store). A real
    process restart round-trip is `[manual]`.

## 4. F-082 — Search

15. **⌘F toggles + focuses + selects-all; Esc hides + clears; Find button
    mirrors.** Expected: ⌘F opens the bar and selects the input; Esc-in-input
    hides+clears; the Find toolbar button reflects the bar's visibility;
    visibility persists to `settings.viewer.find_widget_visible`.
    `[kittest: cmd_f_toggle_persists_find_visibility]`,
    `[kittest: esc_in_focused_input_hides_and_clears_bar]`.
16. **Debounce (300 ms, ≥2 chars at fire time).** Type quickly; search fires
    300 ms after the last edit only when ≥2 trimmed chars remain at fire time
    (deterministic vs Buzz's edit-time-only race, ledger #5); an emptied query
    clears immediately. The pure `debounce_decision(elapsed, chars)` is
    unit-tested (no sleeping);
    `[kittest: search_selects_matching_row_and_shows_label]` drives a real
    debounce crossing via a backdated `last_edit`.
17. **Match select + label + next/prev wrap.** A match selects+center-scrolls
    its row (Timestamps) or highlights+scrolls the range (Text/Translation);
    the label reads `K of N matches` / `No matches found` / `… of 100+
    matches` (byte-exact core `results_label`); ⌘Return/⇧Return and the ↑/↓
    buttons wrap modulo; Return-in-input = next.
    `[kittest: search_selects_matching_row_and_shows_label]`,
    `[kittest: nav_wraps_modulo]`,
    `[kittest: enter_in_focused_input_advances_to_next_match]`,
    `[kittest: translation_matches_append_after_text_matches]` (two-pass order).
18. **Mode switch re-runs an active search.** With a non-empty query, switch
    modes → the search re-runs against the new haystack (no debounce/length
    gate, Buzz parity). Covered inside the search kittests above (mode-aware
    `run_search`); a live mode-switch-with-query is `[manual]`.

## 5. F-083 — Synced playback

19. **Loading / failed player states.** On open, the player row shows a
    disabled "loading…" affordance until the background decode lands; a
    missing/undecodable file → disabled controls + a tooltip naming the cause;
    table/edit/search/export still work.
    `[kittest: player_failed_state_disables_controls_with_tooltip]`.
20. **Play/pause, scrubber, time label.** ⌘P / the play button toggles; the
    scrubber live-seeks on drag (releasing >2000 ms outside a loop range clears
    it); the `H:MM:SS / H:MM:SS` label tracks position.
    `[kittest: controls_bar_appears_on_play_in_timestamps_mode]` (auto-show on
    play); live audio + pointer drag are `[manual]` (executed windowed via the
    A/V-drift run — real audio device, real playback).
21. **Loop / follow / speed.** Loop Segment wraps `end → start` sample-exactly;
    Follow Audio selects+centers the playing segment; the speed combo
    (0.5–2× presets, free text clamped 0.1–5.0, `%.2fx` echo, ±0.05 steppers)
    audibly changes rate (Buzz's was mute, ledger #2) and persists globally.
    `[kittest: speed_combo_echoes_clamped_value]`; loop/follow state-machine
    unit tests over an `AudioOutput`-backed `Player`
    (`loop_toggle_reenable_jumps_when_playing_outside_range`,
    `follow_audio_highlights_containing_segment`). Audible speed + follow-scroll
    on a real screen are `[manual]` (playback executed windowed below).
22. **Video sync spot-check (audio clock is master).** For a video transcript,
    the pane shows the frame for the current audio position; A/V stays in sync
    with no drift correction (single master clock, ADR-019). **Executed
    windowed** via the A/V-drift run below — p95 |audio − frame_ts| well within
    the ±50 ms gate over a full 10-min run.
23. **Current-segment frame + follow update only while playing.** The bottom
    frame shows the segment under the playhead (or the clicked segment); a
    paused scrub does not move it or the follow selection (ledger #15), a
    segment click still does. Unit-tested (`segment_at` binary-search,
    is_playing gate); live is `[manual]` (playback executed windowed).

## 6. F-084 — Export from viewer

24. **Export menu: 6 entries, translation-gated, native dialog, byte-equal
    writers.** The Export button lists `{TXT,SRT,VTT} × {Text,Translation}`
    ("SRT - Text" label shape); the Translation half is absent without
    translations. Selecting one resolves the default filename via the shared
    template engine, defaults the directory to the per-transcript last-export
    folder (schema v2) else the input dir, opens a native save dialog, and
    writes via the **shared M1 `write_format`** (byte-identical to the queue's
    export). Success flashes the written path; a write error shows an inline
    banner.
    `[kittest: export_entry_writes_file_and_toasts]` (drives the real menu click
    through a scripted save dialog, asserts the written bytes + flash +
    persisted folder), plus the snapshot `export_writes_via_shared_writer`
    (all 6 combos byte-equal `write_format`). The **native save dialog itself**
    (`rfd`) cannot run under kittest and is `[manual]` — same class as M3's
    file/folder dialogs.

## 7. F-086 — Resize / merge

25. **Resizer window opens; section enablement by word-timestamps.** The Resize
    toolbar button opens a resizer window (deferred viewport, one per source,
    focus-on-reopen); Settings/Extend/Resize/Merge sections render with
    Buzz-exact labels/defaults; **Resize** is enabled iff word-timestamps off,
    **Merge** iff on (from `load_task_spec` else `spec_from_columns`).
    `[kittest: resize_button_disabled_with_word_timestamps]` (the gate).
26. **Extend / Resize / create-new vs in-place.** Extend endings (`min(end +
    amount, next.start)`); Resize via the srt_equalizer port; create-new copies
    the transcript (translations dropped) while in-place replaces segments;
    the resizer window closes after Extend/Resize (ledger #19).
    `[kittest: resize_end_to_end_creates_new_completed_row]` (drives a real
    resize → a new Completed row + the originating viewer/resizer close +
    `TasksVm` refresh), plus the differential port tests (below). Live pointer
    interaction is `[manual]`.
27. **Merge (regroup).** Merge builds the `mg`/`sp`/`sl` regroup string from the
    checkboxes (overridable by `HUMM_MERGE_REGROUP_RULE`), runs on a worker
    thread (window hides while running), and on completion closes the resizer
    *and* the originating viewer (ledger #20). The regroup + resize ports are
    **differential-verified** against genuine pinned Python (16 `regroup` + 12
    `resize` committed fixtures, ADR-020) — this is the `diff` half of F-086's
    `unit + diff` method, run end-to-end on this machine. Live merge in a real
    window is `[manual]`.
