# M3 GUI Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship humm's eframe GUI shell — import → queue → progress → done — with the M2-carried queue-hardening tickets, per `docs/superpowers/specs/2026-07-21-m3-gui-shell-design.md` (the spec; read it before any task).

**Architecture:** New `humm-gui` binary crate (eframe/egui 0.35) bound to the existing core queue/store; core gains an in-task artifact-ensure path (non-modal downloads), retry/rename/notes/delete, StoreWriteFailed events, single-instance locks, and telemetry. View-models hold UI state only; repaint on events.

**Tech Stack:** eframe/egui_extras/egui_kittest 0.35, rfd 0.17, fluent 0.17 + unic-langid 0.9, open 5, regex 1, fd-lock 4, existing core (flume, rusqlite, reqwest).

- Every commit passes `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`.
- Build env on this machine: `export CARGO_HOME="$PWD/.cargo-home"`; cargo registry unpacking, local TCP test servers (~16 `models::` tests), and GPU/Metal loads need the sandbox lifted.
