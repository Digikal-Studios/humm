##### 4. Decisions already made
Use a current-run manifest, not localhost/name heuristics. New `OwnedRustTarget` dataclass records run ID, source SHA, binary path/hash, DB name/host/port/system identifier/data directory, PostgreSQL PID/start identity, and each supervised API/worker PID/start identity plus its exact DB binding. Manifest lives only under this run's scratch; credentials are never logged. `load_owned_target(path: Path) -> OwnedRustTarget` must validate run ID, scratch containment, liveness/start identity, file hash and explicit URI binding before any DB mutation; a stale manifest is an error. API adoption is forbidden: fixtures must spawn through the supervisor or consume its still-owned child record. Keep protected ports 8016/8017 refused; reject libpq redirect/service/options inputs and implicit DB discovery.

Make `pytest_configure` select/validate mode before DB contact. Collection-only performs no DB cleanup/contact. Rust/SDK-only mode never runs the Python sweeper. Ordinary Python cleanup accepts only DBs created and recorded by the current-run fixture; obsolete unowned databases are left alone. This deliberately removes ambient stale-DB cleanup.

The foreground runner provisions PostgreSQL 17/pgvector using the read-only existing tools at `/paperclip/instances/default/workspaces/8006544b-34a8-45a9-b9c3-f3b42ef9eb97/pg17/root`, a new scratch initdb directory/socket, allocated loopback port, 32MB shared buffers and 40 connections. Copy the owned-process/finally pattern from the [archived validation fixture](https://repo.digikal.com/jawad/infrastructure/src/branch/main/docs/paperclip/shutdown-2026-10-03/issues/DIG-277.md#document-validation-path); no installation or role/host change. Build source in its own worktree with the mandatory Cargo lock/target/one-job settings, copy/hash while holding the lock, then use that binary's `migrate` for fresh bootstrap. Set all explicit DB aliases to the same owned DB, including Python `DB__CONNECTION_URI`; use a minimal provider-free environment and disable `.env`/config file discovery. No real provider calls.

Runner CLI is `--source PATH --commands-json PATH`, plus `--smoke` for a no-product-test ownership/bootstrap/cleanup check. Command file is a JSON array of `{"cwd":"."|"rust","argv":[...strings...]}`. It supplies the proven DB/binary aliases and manifest to each command, writes per-command logs/exits and a provenance/cleanup JSON report to run scratch, runs foreground, and exits nonzero on any command/provenance/cleanup failure. All Cargo argv must begin with `flock /paperclip/.cargo-build.lock cargo` and include locked/offline/one-job options except fmt. Do not execute arbitrary shell strings. Put the existing repository `.venv/bin` first on each command PATH and record its interpreter/package provenance; set PYTHONPATH to the candidate root so imports use candidate code. PYTHONDONTWRITEBYTECODE=1 keeps source untouched. Require a clean committed source tree; source SHA plus copied binary hash must identify the tested candidate. Reject empty command lists except the explicit smoke mode. The runner may safely provide an ephemeral admin URI to migration tests on its own cluster; no external endpoint is accepted.

Qualifying split reason: QA owns the independently useful, shared safety prerequisite; runtime corrections need its proven fixture and it can start without product changes. Can start immediately: no prerequisite change is needed for this bounded correction.
